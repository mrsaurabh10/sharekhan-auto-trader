# Natural Gas Scalping session-close recovery

Trade 11411 opened on 18 November 2026 at 20:40 IST. The last cached full book was received at 21:26:03. From 23:20 to 23:29:59 the run attempted square-off 590 times against that stale book. The Simulator correctly refused stale fills, but no durable trade-level session-close claim prevented the following morning's ordinary target handler from recording a TARGET_HIT at 09:00. Its ₹8,750 overnight gain is recorded history, not evidence of successful same-session execution.

This fix applies to filled intraday `strategy:MCX_NATURALGAS_SCALPING` positions. Entry rules, ₹1.50 stop/target, profit lock, sizing, daily allowance, subscription settings and historical trades are unchanged.

- The session-close intent is committed to the existing trade row before quotes, broker routing or any fallible fill attempt. It is due from 23:20 IST, on an older position's next calendar day, or whenever a persisted MCX_SESSION_CLOSE remains pending. Target/stop callbacks and direct square-off calls give this closure priority. An orphan placed state with no sell ID is returned to recoverable EXIT_TRIGGERED; a submitted sell keeps its ID/status for reconciliation.
- Each open position owns an idempotent Sharekhan full-book feed independently of an entry subscription/run. Demand is restored after reconnect/restart and retained until persistence confirms flat. Missing routes cannot be released by another watcher. A missing/stale book requests the exact route at most once per 30 seconds per scrip, without marking the cache fresh. MCX demand also opens the existing socket before 09:00 when entry subscriptions are paused.
- Only a coherent, positive, uncrossed, exact-scrip Sharekhan book received within five seconds and after entry can supply the exit bid. Orders are attempted only during the existing weekday 09:00–23:30 MCX strategy window. There is no stale-LTP, entry-price, bar-close or fabricated 23:20 fill. No new broker login or REST quote provider is introduced.
- A five-second position monitor is independent of run/subscription state. It recovers persisted close intent after restart and uses the existing atomic order-placement guard, same-order repricing and chase. Missing quotes create a durable exit-attention record/audit using the existing notification mechanism. Pending broker-order reconciliation stays active while waiting for a quote. Notification delivery/bounded retries retain the existing implementation.

If an external feed cannot recover before the market closes, software cannot guarantee a same-session fill. The position remains explicitly open, marked for attention and owned by session-close recovery; it must not become a normal next-day target win. This is an execution-safety fix, not an asserted improvement to strategy P&L. Actual quote recovery and 23:20 fills still require observation during a market session.

No schema migration or configuration flag is needed. The trade row/exit-attention tables already exist; feed leases are rebuilt from active positions. Tests cover stale 23:20 books, restart/next-morning priority, quote identity/freshness, pending/orphan sell IDs, native claim persistence, feed sharing/reconnect/rate limits, paused subscriptions, and existing FNO/MCX exit behavior.
